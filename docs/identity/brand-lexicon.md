## Architecture and Development Terms

The original Development vocabulary — Modularity, Scalability, Maintainability, Performance, Accessibility, Reusability and Progressive Enhancement — remains valid as candidate brand/platform language.

Current governance clarifies that these concepts should not be used to justify premature abstraction.

For example, `Reusability` does not require extracting a shared system before genuine reuse exists.

This clarification does not redefine the terms; it records how later project governance constrains their implementation interpretation.

## Collection / Series Terminology

If future Lexicon work defines `Collection`, `Series`, `ArtworkSeries` or `Curation`, it must distinguish visitor-facing artistic language from canonical domain-model terminology.

Current architecture establishes:

`ArtworkSeries` = canonical domain model

`Collection` = valid editorial/discovery terminology

The Lexicon should not accidentally create a second persistence concept through language alone.

## Future Ecosystem Vocabulary

As the platform evolves, future concepts related to Collector experiences, Marketplace, Virtual Museum, Academy, Community, exhibitions, immersive environments or other approved/planned directions may be considered for the Lexicon when they become philosophically meaningful.

They should not be added merely because a feature exists.

The Lexicon governs enduring meaning, not feature inventory.

## Governance — Reinforced

The original governance remains authoritative:

new concepts belong only when they make a meaningful addition to Del Carmen's philosophy, and existing definitions should evolve only to improve clarity without compromising identity.

Future definition work should preserve explicit status so that:

- Candidate does not mean Approved.
- In Progress does not mean Canonical Definition Complete.
- Implementation vocabulary does not automatically become brand vocabulary.
- Future concepts are not removed merely because they are not implemented.
